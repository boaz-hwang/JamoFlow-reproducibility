# Phase 2d protocol addendum: autoregressive generation validity

> 사전 고정일: 2026-08-10
>
> 상태: **generation 결과 확인 전 고정**
>
> 상위 protocol: [Phase 2 Korean causal protocol §9](./10-phase2-korean-causal-protocol.md)

## 1. 기존 문서의 모호성 해소

기존 문서의 `held-out Korean prefix 256개`는 **prompt 수 256개**를 뜻한다. Prompt 길이는 128 bytes, continuation은 128 bytes로 고정해 최종 prefix horizon을 학습과 같은 256 bytes로 맞춘다.

이 addendum은 다음 빈칸을 결과 전에 고정한다.

- prompt 선택 알고리즘
- partial prefix의 patch 재구성 규칙
- sampling RNG와 top-p 구현
- UTF-8 hard-mask의 DFA와 실험 범위
- Gate H validity 판정

## 2. Prompt 선택

Phase 2와 같은 Korean Wikipedia content-hash `test` stream을 쓴다. 각 256-byte row의 첫 128 bytes 중 다음을 모두 만족하는 candidate만 남긴다.

1. row start가 global UTF-8 codepoint boundary
2. byte 128도 global UTF-8 codepoint boundary
3. 128-byte prompt의 letter codepoint 중 precomposed Hangul 비율 ≥80%
4. strict UTF-8 decode 가능

Exact duplicate prompt를 제거한 뒤 prompt bytes의 SHA-256으로 정렬해 처음 256개를 선택한다. Hash와 prompt자체, source row index는 저장하지 않는다. Candidate가 256개 미만이면 실험을 실패 처리하고 기준을 완화하지 않는다.

## 3. 모델과 policy

5개 seed(1,729 / 2,718 / 31,415 / 57,721 / 65,537)에서 다음 기존 checkpoint를 평가한다.

| 라벨 | Checkpoint | Online policy |
|---|---|---|
| C0 | `fixed_byte_6` | 관측 prefix의 6-byte fixed starts |
| C1 | `causal_codepoint_grid` | fixed 256-byte horizon의 관측 가능 codepoint-grid decisions |
| W | `causal_whitespace_grid` | fixed horizon의 whitespace event/deadline decisions |

C1/W의 모든 경계는 `sequence_length=256`, `require_complete=False`로 관측된 prefix에서만 계산한다. 현재 마지막 open patch는 현 prefix 끝까지 연장한다. 새 byte를 생성할 때마다 전체 prefix와 patch matrix를 재구성하며 future generated byte를 경계 결정에 쓰지 않는다.

HF BLT cache는 진행 중인 patch의 global representation을 이 참조 구현과 동일하게 갱신하는 incremental policy API를 제공하지 않는다. 따라서 `use_cache=False`로 full prefix를 재계산한다. 이 실험의 wall time은 production decoding latency나 speedup 근거로 쓰지 않는다.

## 4. Decoding

각 policy·seed·prompt에서 정확히 128 bytes를 생성한다. EOS가 없는 256-byte vocabulary이므로 early stop을 하지 않는다.

### Greedy

Logit argmax. Tie는 낮은 byte ID가 선택되는 framework 기본 순서를 따른다.

### Sampled

- temperature 0.8
- top-p 0.95
- logit 내림차순, 동점은 낮은 byte ID 먼저
- 누적확률이 0.95를 처음 넘는 byte까지 포함
- 남은 확률을 재정규화해 NumPy PCG64로 표본
- RNG stream은 `(model seed, prompt rank)`로 고정하고 policy 간 common random numbers를 쓴다

모든 probability 계산과 sampling은 CPU float64에서 한다. Batch size가 결과를 바꾸지 않도록 prompt별 RNG를 분리한다.

## 5. UTF-8 DFA hard-mask control

Unconstrained 생성과 섞지 않고 별도 control로 보고한다. Standard UTF-8 DFA로 다음 byte 후보를 제한한다.

- ASCII: `00–7F`
- 2-byte lead: `C2–DF`
- 3-byte lead의 `E0`/`ED` second-byte restriction
- 4-byte lead의 `F0`/`F4` second-byte restriction
- continuation: `80–BF`
- overlong, surrogate, `>U+10FFFF`, `C0/C1/F5–FF` 금지
- 남은 generation budget 안에 codepoint를 닫을 수 없는 multi-byte lead 금지

구조 구현 검사를 위한 control이므로 대표 seed 1,729의 C0/C1/W, greedy/sampled에만 실행한다. 256개 모든 continuation이 strict UTF-8 valid가 아니면 구현 실패로 처리한다. Hard-mask 결과로 unconstrained model의 우월성을 주장하지 않는다.

## 6. Metrics

생성 text/sample은 저장하지 않고 조건별 aggregate만 남긴다.

1. strict UTF-8 valid continuation rate
2. U+FFFD replacement-character-free rate
3. valid conjoining-Jamo transition rate
4. valid continuation의 generated bytes/codepoint 평균·중앙값
5. 유효/invalid count
6. 조건 실행 시간; speed claim에 사용하지 않음

Jamo transition validator는 canonical/extended conjoining Jamo를 `L + V + optional T`로 검사한다. Precomposed Hangul syllable과 compatibility Jamo는 그 자체로 invalid transition으로 간주하지 않는다. UTF-8 invalid인 continuation은 Jamo-valid으로 세지 않는다.

## 7. Gate H validity component

Scale-up 후보 W에 대해 각 unconstrained decoding mode에서 5-seed 평균

```text
UTF8-valid-rate(W) − UTF8-valid-rate(C0) >= −0.01
```

이어야 한다. Greedy와 sampled 중 하나라도 −1 percentage point 미만이면 Gate H validity stop condition이 발동한다. Seed별 difference와 paired-t interval은 보고하지만 기존 stop rule을 사후적으로 더 엄격하게 바꾸지 않는다.

Gate를 통과해도 compact model의 자연어 생성 품질을 입증하지 않는다. 이 단계의 목적은 patch policy가 byte-level structural failure를 키우는지 검사하는 것뿐이다.
