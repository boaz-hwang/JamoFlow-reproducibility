# Valid-output actual-inference correction

> 작성일: 2026-08-12
> 상태: **actual-inference artifact 생성 전 결과맹 교정**
> 선행 감사: [Actual-inference protocol integrity audit](./57-actual-inference-protocol-integrity-audit.md)
> 적용: compact actual inference와 publication-scale raw/BPE benchmark

## 1. 교정 시점

이 교정 시점에 `runs/phase3-actual-inference`,
`artifacts/phase3-actual-inference`, `results/phase3-actual-inference`는 존재하지
않았다. Initial S/E/EC family는 여전히 실행 중이었고 개별 S/E/EC 품질 값도
열지 않았다. 따라서 아래 변경은 관측된 latency, generation 또는 candidate
선택에 맞춘 사후 수정이 아니다. Training data, model weight, patch policy와
quality gate도 바꾸지 않는다.

## 2. 발견한 protocol drift

Protocol v3의 compact runner는 free-running에서 정확히 128개의 raw byte를
생성한 시간을 쟀다. 종료 byte가 UTF-8 scalar 내부이거나 그 전에 illegal
transition이 발생해도 timing array 자체는 완성됐고, 후보의 strict-valid rate가
reference보다 2 percentage points 이상 낮지만 않으면 gate를 통과할 수 있었다.
두 모델이 모두 절대적으로 낮은 유효성을 보이는 경우도 배제하지 못했다.

반면 최신 문헌 감사와 publication BPE protocol은 이미 다음 estimand를
고정했다.

- controlled replay: 동일 held-out source UTF-8 bytes의 time-to-N
- free running: 최소 N개의 **valid UTF-8 bytes**를 완성할 때까지의 시간,
  overshoot와 failure

즉 compact 구현만 이전 raw-byte horizon에 남아 있었다. 사용자가 요구한
“실제로 쓸 수 있는 모델 추론 효율”과도 맞지 않는다.

## 3. 왜 unconstrained 실패 prompt만 제외하지 않는가

Unconstrained greedy stream이 illegal UTF-8 transition을 한 번 만들면 그
prefix에는 `time-to-128 valid bytes`가 존재하지 않는다. 이때 가능한 단순
처리는 모두 편향을 만든다.

1. 실패 prompt를 latency 집계에서 제외하면 model과 policy가 만든 실패에
   조건부로 표본을 고르는 missing-not-at-random 분석이 된다.
2. 실패에 임의의 256/512-step timeout을 부여하면 speed 결론이 model이 아니라
   cap 선택에 종속된다.
3. illegal byte가 나온 뒤 parser를 임의로 복구하면 실제 생성 stream과 다른
   output을 측정한다.

따라서 positive systems gate는 후보와 reference 모두에 동일한 strict RFC 3629
DFA transition mask를 적용한다. Grammar compilation에 해당하는 8개 reachable
state mask 생성은 trial 밖에서 한 번 수행한다. 각 step의 mask 적용, device
argmax, host byte 전달, DFA state transition, stop 검사, selector/router와 cache
update는 모두 timing 안에 둔다.

이 decoder는 **horizon closure mask가 아니다.** 128번째 byte에 맞춰 ASCII를
강제하지 않고 다음 UTF-8 transition의 합법성만 제한한다. 128 bytes 이상에서
처음 accept state에 도달하면 멈추므로 byte model의 output은 128--131 bytes,
overshoot는 0--3 bytes다. 마지막 output 뒤 사용하지 않을 next-logit forward는
계산하지 않는다.

## 4. 유지되는 primary estimand

Controlled replay는 바꾸지 않는다. 같은 128-byte strict-UTF-8 held-out
continuation을 두 model에 넣고, prompt prefill final logit과 정확히 127회의
feedback forward로 128개 conditional output을 계산한다. 이는 output divergence가
없는 primary systems estimand다.

Free-running strict-DFA greedy는 실제 valid-output 경로를 확인하는 secondary
estimand다. 후보와 reference의 생성 내용과 boundary path가 다른 사실은 숨기지
않는다. Candidate의 0--3 byte overshoot가 reference와 다를 수 있으므로 실제
emitted bytes와 forward 수를 그대로 timing하고 함께 보고한다. 최대 세 step의
차이만으로 10% speed gate를 설명할 수 있는지도 진단한다.

## 5. Protocol v4와 재구성 가능한 artifact

단일 protocol source를 v4로 올리고 free-running mode를
`free_running_utf8_greedy`로 명시했다. 각 mode×role×prompt×repetition에 다음
content-free 배열을 추가한다.

- emitted output bytes
- decode forward steps
- runtime-observed bytes
- overshoot bytes
- valid-output stop 여부
- replacement-character-free 여부
- broad conjoining-Jamo transition 여부
- output Unicode codepoint 수

Runner와 summarizer는 다음 항등식을 독립 검증한다.

```text
decode_forward_steps = emitted_output_bytes - 1
runtime_observed_bytes = prompt_bytes + decode_forward_steps

controlled:
  emitted_output_bytes = 128
  overshoot_bytes = 0

free running:
  128 <= emitted_output_bytes <= 131
  overshoot_bytes = emitted_output_bytes - 128
  valid_output_stop = 1
```

Greedy output은 repetition 간 결정적이어야 한다. Report의 emitted/overshoot,
replacement, Jamo와 bytes/codepoint aggregate는 위 private numeric arrays에서
다시 계산되어야 한다. Prompt, continuation, generated bytes와 decoded text는
저장하지 않는다. Compact summary schema는 이 변경 때문에 v2로 올린다.
Raw time-to-output gate와 별도로 실제 emitted bytes 기준 ms/byte·bytes/s,
Unicode codepoints/s와 최소-valid-byte 기준 end-to-end rate를 보고한다. 이
정규화 수치는 output-unit 해석 진단이며 latency gate를 대체하지 않는다.

## 6. Gate 교정

Free-running latency는 최소 128 valid bytes를 완성하는 end-to-end 시간으로만
통과할 수 있다. 후보와 reference의 모든 measured output은 strict-valid여야
한다. 이 절대 조건을 상대적 `candidate - reference >= -2pp` 규칙으로 대체하지
않는다.

U+FFFD는 합법적인 Unicode scalar이므로 strict DFA만으로 제거하지 않는다.
Replacement-character-free rate는 계속 품질 guard로 두되 다음을 모두 요구한다.

- 전체 candidate mean이 reference보다 2pp 넘게 낮지 않음
- 최소 4/5 seed가 같은 2pp margin 안

Publication-scale gate도 공통 valid-output contract가 검증되고 세 seed 모두의
completion rate가 100%일 때만 free-running speed를 인정한다. Raw, 16K BPE와
32K BPE는 모두 최소 128 valid raw bytes의 첫 accept state라는 같은 의미를
사용하고 tokenizer별 overshoot와 failure를 기록해야 한다.

BPE의 variable-byte token에 대한 state-specific mask와 종료 규칙은 후속
[BPE token UTF-8 transition correction](./72-bpe-token-utf8-transition-correction.md)이
구체화한다. Byte model의 0--3 byte overshoot bound를 BPE token output에 적용하지
않는다.

## 7. 해석 경계

공통 DFA를 적용한 latency pass는 다음을 뜻한다.

> 동일한 validity-preserving decoder 아래에서 candidate가 quality-qualified
> reference보다 최소 128 valid UTF-8 bytes를 더 빨리 생성했다.

이는 candidate가 UTF-8 문법을 weight 안에 더 잘 학습했다는 증거가 아니다.
Intrinsic unconstrained validity는 기존 fixed-horizon generation suite와 DFA
failure taxonomy에서 별도로 보고하며 latency 수치로 사용하지 않는다. DFA는
제안한 whitespace boundary policy의 일부나 독점적 이점으로 주장하지 않는다.

## 8. 검증

Strict DFA의 모든 8개 reachable state와 256개 next byte를 exhaustive unit test로
검사했다. Overlong sequence, surrogate와 U+10FFFF 초과를 거부하고, 1-byte
target에서 3-byte scalar가 2-byte overshoot로 종료되는 경우, illegal raw argmax가
mask되는 경우, timing-array tampering과 summary 재구성을 포함한 focused test
57개가 통과했다. 전체 suite와 실제 MPS smoke는 실행 중인 S/E/EC family가 끝난
뒤 다른 MPS process가 없는 상태에서 수행한다.
